# ابزارهای محاسبهٔ شمارهٔ صفحه‌های فهرست مطالب

این پوشه فقط ابزار است و بخشی از متن رساله نیست.

## چرا شماره‌ها غلط بودند
فهرست مطالب یک فیلد واقعی Word است (`TOC \o "1-4" \h \z \u`) که هر مدخل آن یک
فیلد `PAGEREF` به یک نشانه (`_Toc0000xx`) در متن دارد. عددِ دیده‌شده، «نتیجهٔ
ذخیره‌شدهٔ» آن فیلد است و تا وقتی فیلد به‌روزرسانی نشود، همان عدد قدیمی می‌ماند.
محتوای رساله بعد از آخرین ذخیره در Word زیاد شده بود، بنابراین همهٔ عددها کهنه
مانده بودند (در بدنه تا ~۱۰ صفحه اختلاف).

نشانه‌های `w:lastRenderedPageBreak` داخل فایل هم کهنه‌اند: مثلاً بین دو نشانهٔ
پیاپی حدود ۶٬۰۰۰ نویسه متن ۱۴ پوینتی قرار دارد که در یک صفحه جا نمی‌شود، پس
نمی‌شد از آن‌ها به‌عنوان مرجع استفاده کرد.

## روش
`layout.py` صفحه‌بندی Word را بازسازی می‌کند: اندازهٔ قلم هر run، فاصله‌های
پاراگراف، `keepNext`/`keepLines`، کنترل بیوه/یتیم، پانویس‌ها، شکست صریح صفحه و
شکست بخش‌ها. سه ضریب مدل با دادهٔ واقعی کالیبره شده‌اند و نتیجه با دو شاهد
مستقل می‌خواند:

* کل صفحه‌ها: **۱۰۹** — برابر با `docProps/app.xml` خود فایل؛
* «بند چهارم: تحلیل اصل ۱۱۰…» روی صفحهٔ **۷۶** — همان چیزی که در Word دیده شد.

## اجرا

```bash
python3 tools/fix_toc.py     # ساخت فایل اصلاح‌شده
python3 tools/verify2.py     # بررسی اینکه فقط فهرست مطالب عوض شده
python3 tools/bmcheck.py     # تطبیق هر مدخل با نشانهٔ خودش در متن
```
